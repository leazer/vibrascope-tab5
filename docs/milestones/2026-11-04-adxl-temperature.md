# TAB5 改为显示 ADXL357 温度

需求：温度显示从 ICM FIFO 温度切到 ADXL357，低频更新，避免影响实时流。

- 新增可忽略的 `0x21 TEMPERATURE` 解析/事件，不更改既有状态、波形、姿态及保留字段。16B payload / 35B 整帧，具体字段和探头实现见另一仓 `docs/milestones/2026-11-04-adxl-temperature.md`。
- 不增加主机请求，每秒最多一帧温度，与 FETCH 共用预算。旧探头没有温度遥测时显示 `ADXL -- C`，不回退到 ICM 或把标定时温度冒充实时温度。
- 以 `25 + (1885 - raw) / 9.05` 换算，显示一位小数。温度是未独立标定的 ADXL 芯片温度，不能宣称环境温度精度。
- `ADXL xx.xC*`：停止采集后的末次读数。ADXL 停机温度通道也停机，不为读温度改变 STOP/待机功耗。关于页有 `*` 说明。
- 采集中，仅传感器采样时间戳变化才能刷新 3.5s 超时；重复旧缓存不延寿。断线和重新开采清除旧值。停止后保存最后有效值，姿态继续独立更新。
- ICM 原始温度字段继续用于原始文件记录及原有算法，UI 不再使用它。

验证：主机协议/温度解析/FETCH/停止回归通过；新增重复缓存超过 3.5s 失效、真实新观测恢复与重连清零测试。Desktop、TAB5 构建通过。探头 SPI、标定、姿态、帧封装、采集、协议回归通过；四模式零错误零警告；标定区烧录前后 4096B 哈希一致。

实机：两端均已更新并校验，用户回复“已测试”。串口日志 `build/adxl-temperature-device.log` 确认 ADXL 温度约 33–36°C，RUN live=1，STOP live=0。连续 RUN 数个 5s 窗口内 CRC、超时、重试、接收溢出与探头队列丢样均零，gap/rejected 累计值稳定；反复启停间累计 gaps 曾增长，不宣称全程零间断或精确 100% 交付。原有启动时间线收敛窗口仍会拒绝 TIME_UNCERTAIN 帧。此验证为短时功能/采集检查，未做长期稳定性或温度绝对精度验证。

独立代码复核发现重复旧缓存会刷新新鲜度的问题，已通过 `TemperatureAge` 按采样时间/配置去重并增加回归；复核确认修正无遗留重要问题。
