# VibraScope

主界面采用 1280×720、左侧 294 px 的已确认布局。`AppVibescope` 与 launcher 一样，只负责 View 生命周期；View 内按 `view_panels.cpp`、`view_plots.cpp`、`view_windows.cpp` 拆分。弹窗使用仓库 `ui::Window` 的弹簧过渡，按钮使用 smooth_ui_toolkit 的持有式包装。

- 左侧：真实 Logo / 关于、传感器坐标系姿态、温度、加速度指标、可点击的 RMS 小趋势、采集与录制控制。
- 右侧：时域、FFT、时间–频率瀑布、三轴 Gyro；底部选择单图 / 上下双图 / 上一下二，配置跟随选中图。
- RMS、峰值、峰峰值、峰值因子和普通峭度使用去直流数据。点击左栏统计行可统一选择加速度源、量程及 0.5 / 1 / 2 s 统计窗，统计行显示实际窗长。
- FFT：最近最多 2048 点、Hann 窗、按窗增益归一的峰值幅度，横轴到 Nyquist。瀑布保留每个显示频带中的最大幅度，避免窄峰漏掉；颜色范围 −60…0 dB re 1 g。
- Gyro 使用 ICM 的真实角速度（°/s），不会把左侧的加速度 RMS 换成角速度单位。显示姿态归零不写探头标定；Yaw 为相对航向。
- 三维模型的归零观察方向：Z 向上，+Y 朝屏幕里（透视为右上），+X 保持原来的右下方向。薄面法线为 Z；只调整观察投影，不交换传感器数据、姿态角或标定轴。
- 加速度按实际采集量程换算。ADXL 支持 ±10 / ±20 / ±40 g，ICM 支持 ±2 / ±4 / ±8 / ±16 g，Gyro 使用 ±500 °/s。运行中换量程会重新配置并开始一段新采集。
- 独立 worker 持续 FETCH；FFT/统计由 CPU1 的独立低优先级分析线程执行，计算时不持有 LVGL、采集或结果交换锁。UI 只提交最新快照并读取已完成结果；分析忙时待处理帧被最新帧替换，不累积任务。结果按有效性、代际和采样率档位隔离，允许时间估计器的正常微小漂移。USB 断开后重建 client、重新 HELLO/查询标定。CRC/时间不可信/溢出等完整性故障、序号缺口、config/segment 变化时清空对应分析窗；接近量程只告警，保留测得样本。
- 桌面明确标注 DEMO，走同样换算和分析路径；TAB5 使用 USB 探头，不自动开始测量。
- 单次触发比较 ADXL 三轴绝对加速度（包含重力），达到配置阈值后停止采集、保留最终波形。
- 电量、BT/WiFi 未有可靠状态接口，显示 `--`，不虚构电量和联网状态。
- 启动仅安装 VibraScope。工厂 `AppLauncher` 保留源码用于组件与风格参考，不在不可见的后台持续刷新演示面板。大波形预先光栅化为 RGB565 画布，保留抽取区间的极值；小 RMS 图批量更新数据数组。

## 原始录制

独立低优先级写线程、有界 64 批队列，采集线程不等待 SD I/O。TAB5 写 SD 卡 RECORDS 目录中的 `VNxxxxxx.VNR`，桌面优先写 TEMP。录制错误会提示。拔出探头会结束当前录制。

文件均为小端。v2：8 字节 `VNRAW\x02\x00\x00`；随后 `uint32 valid_flags, generation` 和 16 个 float32（ADXL bias×3、scale×3、ICM bias×3、scale×3、gyro bias×3、标定温度）。随后每批 40 字节 `<IIIIQQII>`：stream/config/segment/quality/first_sequence/first_time_us/period_q16/count，后跟 count 条 `<7i>`（6 个原始通道、temperature_raw）。ADXL 只有前三通道有意义。保留质量标志与分段，可离线核对丢批和不确定时间。

v3 保留 v2 的标定头，在每批头的 `count` 后增加一个 `uint32 accel_range_g`，记录该批的实际加速度量程。`python tools/inspect-vnr.py file.vnr --csv file.csv` 可验证并导出带标定的物理量，兼容 v1 和 v2 文件。

长按「录制」后松手可打开文件列表，结束录制后可勾选并确认删除。点右上角状态图标，在「设备设置」里选「连接电脑」，通过 USB-C 将 SD 卡作为可读写磁盘导出。导出时暂停采集并卸载 TAB5 上的 FAT。退出前先在电脑上安全弹出磁盘。如果 TAB5 仍显示导出模式，再点「退出导出」恢复 SD 挂载和 Serial/JTAG 下载口。导出期间 COM 口暂时消失。

新录制保存到 SD 卡的 `RECORDS` 目录。底栏「截屏」将当前画面保存为 `SCREENS` 目录中的 BMP。旧录制保留在根目录，也会继续出现在录制列表里。

数据源、两路量程、统计窗、触发阈值、录制停止方式、布局、侧栏和各图设置自动保存到 SD 卡的 `CONFIG` 目录。启动时读取最新有效配置。没有 SD 卡或有效配置时使用默认值。采集和录制状态、游标位置以及姿态归零参考仅在当前会话内生效。

「探头设置」的数据显示可选 XYZ 或合成矢量。各图可跟随全局或单独选择显示轴，选择会随配置保存。合成振动时域取三轴去直流后的瞬时幅值，频谱与分频段 RMS 按三轴功率合成。

## 素材与验证

`tools/generate-vibescope-assets.py` 从已确认的 Logo 生成 LVGL 像素数据，并从本机字体生成所需中文子集；需要 Pillow、fontTools、lv_font_conv。生成结果已入源码，日常编译不需要 Python/npm。

启动资源由 `tools/generate-startup-logo.py` 从原图逐像素拆分主体和蓝点，拆分层白底重组断言与原 Logo 完全一致。主体保持底部升起，蓝点随后以 0.48 s 加速下落；按主体实际坐标定位落点，落点帧提交后触发原启动音效一次。用户已确认整屏重绘可解决主体缺失，但动画变卡；现改为一个连续的中央重绘区（升起 592×268、下落 592×520），主体白底 RGB565 使用 PPA，蓝点保留透明边缘，落位停留时不再重绘。主界面局部刷新不变。`build/vibescope-startup-fast-device.log` 实测升起 1 s 共 29 帧、下落 496 ms 共 15 帧，平均 render 15.97 ms、最大 30.90 ms，音效一次、PPA fallback/errors 与异常均为 0。用户实机确认动画已恢复，主体完整保留；当前版本保留。

验证入口：`tests/host/run-host-tests.cmd`、`tools/build-desktop-windows.ps1`、`tools/build-tab5-windows.ps1`。

### 2026-11-02 硬件加速与刷新

- ESP-DSP 固定 1.8.2，P4 使用 `dsps_fft2r_fc32_arp4_` 的硬件循环与单精度 FMA。不是独立 FFT 外设。32 KiB 私有对齐工作区优先内部 SRAM；不足时允许对齐 PSRAM，表和 Hann 窗按尺寸缓存。桌面及异常初始化保留可移植路径。独立 DFT、微小交流叠加重力、Nyquist 和相邻频点等主机数值回归通过。
- `scope_ppa.cpp` 在当前 LVGL 9.2 / IDF 5.4.4 上增加有限 PPA 绘制单元：大面积不透明 RGB565 图像复制及无圆角纯色填充。小图、透明/缩放/圆角任务继续走原软件绘制。DMA 目的地址、实际容量、行跨度和缓存行边界逐项校验；SRM 前写回同缓存行内已有的软件像素，完成后再交回 LVGL。实机 `active=1 align=128`，图像与填充计数增长，fallback/errors 为 0。
- 显示端原有 PPA 旋转与 LCD DMA2D 保留。仅显示缓冲分配按 DMA 要求对齐；全局 `LV_DRAW_BUF_ALIGN` 保持 4，避免静态图片及现有画布被 128 字节要求拒绝。LVGL 字符串操作采用 CLIB。
- 标签内容未变化时不再调用 LVGL setter，避免重复分配、无效矩形积累及退化全屏重绘。运行时请求 50 ms 刷新；这是请求周期，实际交付帧率以实机渲染计数为准。
- 瀑布在共享的大画布中直接展开 128×32 历史，交给 PPA 原尺寸复制，避免 LVGL 软件缩放；未增加另一份全尺寸像素缓冲。FFT/瀑布要求存在有效频谱，分配失败不会画成零值频谱。
- 串口监测工具曾因 PySerial 默认 DTR/RTS 电平在结束监测时复位设备。`capture-console.py` 改为打开前设置两线非活动、关闭时保持。两次连续开关监测的对照确认后一次无重启；不要再用默认 `Serial(COM10)` 替代该工具。
- `vibescope-render` 的 render 时间包含 flush 和等待，不能将三者再次相加；`frames` 是五秒统计窗中的实际渲染次数，包含姿态、弹窗等局部刷新，不等同于大波形刷新次数。`updates` 可观察主界面数据更新次数。
- 模式切换入口统一规范化源：Gyro 固定取第三路，切回加速度图恢复 ICM。诊断脚本曾绕过下拉框的原有转换，在用户操作为 Gyro 后仅强制修改 kind，导致频谱数组越界；现在统一入口也覆盖该情况，主机回归验证三种加速度图均不能保留 Gyro 源。
- 最后模式回归 `build/vibescope-modes2-device.log`：自动运行约 60 s，依次切瀑布、打开 RMS、关闭弹窗切 Gyro、Gyro 转频谱、三图。双图/瀑布/三图各约 48–52 次数据更新/5 s（约 10 Hz），常态 render 约 57–61 ms；六路后台分析约 25–35 ms（此前约 116–120 ms）。RMS 打开时额外图表开销仍存在，不宣称达到 30/60 FPS。全段 CRC/gap/drop/rx overrun 为 0，PPA fallback/errors 为 0，未出现 panic、看门狗或字体/对齐告警。启动的时间收敛质量拒绝照常保留。

### 2026-11-02 大幅晃动时数据消失

- 原因：探头 `probe_acquisition.c::validate_batch` 在原始任一通道达到 95% FS 时置 `NEAR_FULL_SCALE`，线协议 0x0004 映射 domain `Saturated` (0x10)。ADXL 阈值 498073 count（名义约 9.5 g），ICM 加计/陀螺阈值 31129 count（名义约 15.2 g / 475 dps）。ICM 是加计和陀螺共用的批次标志，不能据此断言选中加速度轴已超 10 g。UI 指标为去直流后的统计，告警针对原始逐样本值。
- 旧 `ScopeRuntime::accept` 将该标志当作致命质量错误，丢弃整批并清空该源历史；ICM 同时清加计与陀螺，异步分析/数值/趋势随后失效。复现日志 `build/vibescope-shake-before-device.log`：rejected 持续增长且 last_quality=10/10，CRC/gap/drop 均为 0。
- 监视界面现在放行仅带接近量程告警的数据，历史和测得波形继续；时间、CRC、断序、格式和溢出故障仍拒收。探头、冻结协议及严格诊断分析选择规则未改。实际削顶无法恢复真实峰值；显示的 RMS/FFT 来自测得样本，并带量程标记。
- `SampleHistory` 保存最近告警样本序号，按实际分析窗口判定是否仍含告警，无额外逐样本标志数组。清空、换段/配置、断序清除旧标志，样本离窗自动解除。异步分析结果携带自身告警，避免误贴新窗口。状态行及图源标题显示黄色“接近量程”，指标行和 RMS 弹窗显示 FS!。
- 回归覆盖告警不清窗/不改 generation、离窗及清空/换段解除、严重标志组合仍拒收、异步结果保留标记。主机回归与桌面/TAB5 构建通过，新增汉字已重新生成字体。
- 修复后 `build/vibescope-range-device.log` 实机已捕获约百批告警，窗口保持约 4036/8042/8042 点；rejected 停留启动 TIME_UNCERTAIN 的 9/114，CRC/gap/drop/rx overrun 均为 0，停止晃动后 window 标志从 1/1/1 恢复 0/0/0。用户实机确认：同样晃动时波形/数值继续显示，并出现“接近量程”提示；当前版本保留。

### 2026-11-02 FFT 动态频点与 dB

- FFT 取消固定 256 点的分组连线。频点少于图宽时全部按原始 bin 位置绘制；密集时按互不重叠的像素区间取最大值，保留峰值原始频率和端点，避免一个边界峰值被相邻组重复使用而产生平台。
- 停止后 FFT 也支持 `+` / `-` 缩放、横向拖动、`Fit` 回到 DC–Nyquist，游标指向当前频率窗口内的原始 bin。FFT 点数或 bin_hz 变化时重置频率窗口，避免最终后台结果到达后频段发生隐式缩放。
- 选择 FFT 图后，“幅值”增加 `dB`：20log10(幅值/1g)，轴标 `dB re 1g`，自动上界、80 dB 可见范围，零幅值转换下限 -160 dB。它是峰值幅度谱，不是 PSD 或 dB/Hz；原始频谱和左侧统计不变。线性自动/固定选项保留，时域和瀑布没有新增此选项。
- Host 测试覆盖边界峰仅输出一次、稀疏真实 bin、空窗口、dB 参考/零值和停止后 FFT 513→1025 bins 或 bin_hz 改变。Desktop 已实测停止放大、频率拖动和 dB 弱频谱显示。实机性能尚待下载验证，本轮未自动下载，前述欠压重启另见对应 milestone。
